# P-003 移动止损 + Agent「放宽」特权 + 主动卖出标准

- 类型：代码策略 + 研究 prompt（`sim/` 结算止损、草稿字段、归因；`docs/automation/prompts/research.md`）；**不改 `config/risk.yaml`**
- 状态：**已批准并实施**（2026-10-27 用户在对话中批准；strategy-v1.6）
- 提出日期：2026-10-27；提出时策略版本：strategy-v1.5；实施后为 strategy-v1.6

## 问题与证据
- 现行卖出规则（代码）只有三条：固定止损（买入时定的止损价，默认成本 −8%，此后不上移）、时间止损（满 20 个交易日且仍亏损）、熔断/暂停时全部强制卖出。Agent 每晚可以主动卖出，但 prompt 没有判断标准。
- 结果：**赚钱的票没有任何代码保护**。一只票涨 30% 后，代码要等它跌回成本 −8% 才动，中间利润全靠 Agent 当晚的主观判断。
- strategy-v1.5（P-001）后单只新仓到 8%–12%、个股上限到 95%，这个漏洞对净值的影响被放大。
- 2024-10 ~ 2026-10 两年规则代理回测（v1.5 口径：单只约 10%、个股上限 95/80/50%、回撤线 15/22/27%；另从 10 个不同起点各跑一遍）：

| 方案 | 全期年化 | 全期回撤 | 不同起点年化中位数 | 不同起点最差回撤 |
|---|---|---|---|---|
| 现行规则 | +4.4% | −12.4% | −5.1% | −29.6% |
| 移动止损 12%（浮盈 ≥6% 后启动） | +2.9% | −11.1% | +2.2% | −17.0% |
| 移动止损 15% | +3.5% | −10.7% | −0.1% | −18.0% |
| 移动止损 20% | +3.4% | −11.9% | −0.1% | −18.7% |
| 浮盈 ≥10% 跌破 MA20 止盈 | −1.7% | −12.6% | −1.1% | −20.5% |
| 时间止损改为"20 天未赚 3%" | −0.6% | −19.8% | −1.4% | −29.1% |
| 止损放宽到 10% | +1.2% | −14.0% | −1.9% | −28.4% |

- 结论：现行规则在 v1.5 仓位下最差回撤贴近 30% 上限；移动止损是唯一同时改善"不同起点中位数"和"最差回撤"的方案。代价是全期年化少约 1.5 个百分点（一路大涨的票会被提前洗出），这正是本提案加入 Agent「放宽」特权的原因。
- 局限：回测是机械代理，未含 Agent 主动卖出；样本约 30–60 笔已平仓；股票池有幸存者偏差。只能说明方向，参数要用实盘数据校准。

## 改动

### 1. 移动止损（代码执行）
- 适用：个股，以及权益/商品类主动 ETF；债券、货币 ETF 和底仓 ETF 不适用。
- 每个持仓新增 `high_close`（持仓以来最高收盘价，按除权比例同步折算，与 `stop_price` 一致）。
- 每日结算时：若 `high_close ≥ 成本价 × 1.06`（浮盈 ≥6% 才启动），移动止损位 = `high_close × (1 − 12%)`。
- 生效止损价 = max(买入时的固定止损价, 移动止损位)；收盘价 ≤ 生效止损价 → 次日卖出，`reason_type = "trail_stop"`。
- 移动止损位只随 `high_close` 上移，从不下调（「放宽」模式除外，见下）。
- 参数放在 `config/strategy.yaml` 的新段 `exit:`（`trail_start: 0.06`、`trail_pct: 0.12`、`trail_wide_pct: 0.20`、`wide_min_gain: 0.15`），属于策略参数，不进 `risk.yaml`。

### 2. Agent「放宽」特权（必须事先声明）
- Agent 在草稿新增的 `holds` 列表里，可给持仓标记放宽：`{"code", "trail": "wide", "reason"}`。
- 放宽后，移动止损位改为 `high_close × (1 − 20%)`，且**不低于成本价**（最坏保本出局，不会让盈利变亏损）。
- 代码校验（`validate_draft` / `sim plan`），不满足的放宽标记剔除并写入 `draft_errors`：
  1. 该持仓当前浮盈 ≥ 15%；
  2. 当前 regime 不是 defense，账户不在 warn / breaker / halt 状态；
  3. `reason` 非空。
- 时效：放宽标记在 `sim plan` 冻结时写入持仓状态，**只对下一次结算有效**。没有续标就自动恢复 12%，不能一次标记长期不管。
- 时点：研究 19:00 写草稿、evening 20:00 先结算再冻结，所以标记总是在触发之前声明，事后不能反悔。
- prompt 约束：只给当晚复核置信度为"高"、且能写出具体理由（业绩/订单加速、所在板块仍强等，不能只写"趋势好"）的持仓标放宽；写不出就不标。
- 放宽状态下触发的卖出记为 `reason_type = "trail_stop_wide"`，便于归因。

### 3. Agent 主动卖出标准（研究 prompt）
- 买入单新增必填字段 `falsify`（1–3 条可检验的证伪条件，例如"三季报扣非同比转负""收盘跌破 60 日线且 3 日未收回"），随订单冻结并写入持仓。
- 每晚复核持仓时，对照 `falsify` 逐条写"触发 / 未触发 / 无法判断（缺数据）"，写入 `journal/research/<日期>.md`。
- **任一条触发：卖出或至少减半**，`reason_type = "exit"`，reason 写明是哪条触发；不卖要写出具体反证，并在下次复核再判断。
- 没有触发证伪条件时，不因"涨多了""感觉要调整"主动卖出，交给移动止损处理。
- 旧持仓（v1.6 之前买入、没有 `falsify`）在下一次复核时补写。

### 4. 归因与看板
- `sim/attrib.py` 的"按离场原因"新增 `trail_stop`、`trail_stop_wide`；另出"放宽标记"小表：被放宽的持仓数、放宽天数、放宽期内最终结果 vs 若按 12% 卖出的结果。
- 测试：移动止损启动阈值、只升不降、除权折算、放宽校验（浮盈不足 / defense / 熔断 / 空理由各一例）、放宽不续期自动恢复、保本下限。

## 不在本提案内（属于 `config/risk.yaml`，需用户另行决定）
- **市场转弱时强制减仓**：现在 regime 降档只拦截新的买单，已有持仓不减。v1.5 后个股可到 95%，进攻转防守时最多会有约 45 个百分点超出上限。建议另议。
- **熔断只卖亏损的票**：现在熔断/暂停时全部强制卖出。回测改善较小（最差回撤 −29.6% → −25.7%），有了移动止损后必要性下降，可后议。

## 预期效果与验证方式
- 实施后 40 个交易日：main 已平仓个股中 `trail_stop` 的平均收益 > 0（说明保住了利润）；最大回撤 ≤ 22%。
- 放宽特权：被放宽的持仓满 8 笔后，平均结果应优于"按 12% 卖出"的反事实结果。
- 证伪标准：复盘日志里每只持仓每晚都有逐条判断；`exit` 类卖出的 reason 能对应到某条 `falsify`。

## 反方论证
- 移动止损会把一路大涨的票提前洗出去，回测里全期年化少约 1.5 个百分点。放宽特权只能挽回 Agent 判断对的那部分。
- Agent 可能滥用放宽（把多数持仓都标成"高"）。代码门槛（浮盈 ≥15%、非防守、每晚续期）加事后归因可以发现，但不能事前杜绝。
- 证伪条件写得太宽松就形同虚设，写得太紧会频繁误卖；需要进化官抽查质量。
- 回测样本小、无 LLM、有幸存者偏差，参数（6% / 12% / 20% / 15%）都是先验值。

## 失效判据与回滚
任一条成立即回滚到 strategy-v1.5 的卖出规则（版本号 +0.1），并写复盘：
- 实施后 40 个交易日内，`trail_stop` 卖出满 10 笔，且其中卖出后 20 个交易日继续上涨超过 10% 的占比 > 50%（说明洗盘过度）；
- 放宽特权满 8 笔，平均结果劣于按 12% 卖出的反事实结果 → 只收回放宽特权，保留移动止损；
- 主动卖出标准实施后连续 2 周有持仓缺少逐条证伪判断 → 视为流程失效，由进化官提出修复。
