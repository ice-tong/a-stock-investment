# 模拟交易与自我进化系统设计

> 目标：用模拟盘长期、诚实地检验这套 Agent 框架。在回撤尽量小的前提下追求更高收益，并让策略在有证据时可控地进化。
> 几个月后，用**事先定好的标准**决定是否小资金跟随实盘。
>
> **实现细节以代码与 `docs/automation/README.md` 为准**；本文描述设计意图，个别路径、时间、账户名可能落后于实现。第四节风控规则与第七节实盘标准的数字以本文件为准。

---

## 一、核心设计原则（最重要的 5 条）

1. **代码管账，Agent 只提建议。**
   账本、撮合、手续费、风控限制全部由确定性 Python 代码执行。Agent 只输出"订单建议"（JSON），由代码校验后成交。
   Agent 永远不能直接改账本、持仓或风控配置，否则收益曲线不可信（LLM 会算错、会"美化"，也可能绕过限制）。

2. **决策先冻结，再看结果。**
   晚上生成的次日订单写入 `orders/YYYYMMDD.json` 后立即计算哈希并 git 提交，第二天只能执行、不能改。
   这样杜绝"事后诸葛亮"，保证模拟成绩是真实的前向测试。

3. **模拟要比实盘更苛刻，而不是更宽松。**
   T+1、涨跌停买不进卖不出、100 股整手、佣金最低 5 元、印花税、滑点、停牌，全部按真实规则算。
   模拟盘跑出来的收益，实盘通常只会更差。

4. **风控规则只有你能改，Agent 只能提议。**
   自我学习可以调整选股逻辑、提示词、权重，但不能放松仓位上限、止损、回撤熔断。
   否则系统在连续亏损后很容易"学会"加大风险去回本。

5. **所有改动可追溯。**
   每笔交易记录当时的提示词版本、模型名称、数据快照。这样才能判断收益变化是来自策略改进、模型更换还是运气。

## 二、每日运行流程

以交易日 T 为例（非交易日自动跳过，交易日历用 `ak.tool_trade_date_hist_sina()`，包含节假日和调休）：

| 时间 | 任务 | 执行者 | 产出 |
|---|---|---|---|
| T-1 晚 20:00 | **盘后结算**：用收盘价给持仓估值、更新净值、检查止损/止盈/时间止损是否触发 | 代码 | `accounts/<账户>/nav.csv`、风控告警 |
| T-1 晚 20:15 | **复盘**：有成交或持仓异动时，复盘当日交易；无交易时只做简短持仓检查 | 复盘 Agent | `journal/daily/YYYYMMDD.md` |
| T-1 晚 20:45 | **初筛**：全市场约 5000 只 → 量化过滤 → 约 30-50 只候选 | 代码 | `data/screen/YYYYMMDD.csv` |
| T-1 晚 21:00 | **研究**：候选池精选 3-5 只做深度分析（复用现有 8 个子代理）；同时逐只复核现有持仓 | 首席研究员 + 子代理 | 研究报告 |
| T-1 晚 22:00 | **决策**：组合经理 Agent 输出次日订单建议（买/卖/调仓、目标仓位、限价、放弃条件、理由、置信度） | 组合经理 Agent | 订单草稿 |
| T-1 晚 22:10 | **风控校验 + 冻结**：代码检查所有硬性限制，不合规订单直接拒绝或缩量；通过后写入并提交 git | 代码 | `orders/<交易日>/<账户>.json`（冻结） |
| T 日 15:10 | **执行**：按冻结订单、以 14:45 的价格撮合（涨停不买、跌停不卖、限价不满足不成交、超过成交量比例上限只部分成交） | 代码 | `accounts/<账户>/trades.csv` |
| T 日 15:30 后 | 进入下一轮盘后结算 | — | — |
| 每周六 | **周复盘 + 策略进化**：本周收益归因、错误分类、经验提炼，并基于累计证据提出改进提案 | 复盘 / 进化 Agent → 你审批 | `journal/weekly/`、`evolution/` |

**为什么在 14:45 而不是开盘执行？**
开盘时情绪波动大、价格跳空多，晚上做的决策在开盘时最容易失真。14:45 的价格更接近当天的定价共识，也能看到当天是否涨停、跌停或停牌。
如果 14:45 取价失败，就退回用收盘价加滞后惩罚（多扣 0.2% 滑点）成交，并记录原因。

## 三、模拟撮合规则（代码强制执行）

| 规则 | 设定 |
|---|---|
| 初始资金 | **与你计划投入实盘的金额一致**。资金小时整手约束影响很大：例如 1300 元的股票，一手就要 13 万 |
| 成交价 | 14:45 实时价 ± 滑点。滑点按流动性分档：日均成交额 >10 亿取 0.1%，1-10 亿取 0.2%，<1 亿禁止买入 |
| 成交量上限 | 单笔不超过该股当日成交量的 1%，防止小盘股"模拟能成交、实盘成交不了" |
| 交易单位 | 买入 100 股整数倍；卖出可以有零股 |
| 佣金 | 万 2.5，单笔最低 5 元（按你实际券商费率改） |
| 印花税 | 卖出 0.05% |
| 过户费 | 0.001%（双向） |
| T+1 | 当天买入的股票当天不能卖 |
| 涨跌停 | 14:45 处于涨停价不能买入，处于跌停价不能卖出（止损单顺延到下一交易日） |
| 停牌 | 不能交易；持仓按停牌前价格估值并标注 |
| 分红送转 | 按除权除息日调整持股数量与现金（分红计入现金，并扣红利税：持有 1 个月内 20%、1 个月至 1 年 10%、1 年以上免税） |

## 四、风控规则（只有你能改：`config/risk.yaml`）

### 4.1 仓位与空仓：用"底仓 ETF"解决

你提出的"不能长时间空仓"和"回撤尽量小"本身有冲突：强制满仓会放大熊市回撤。建议这样处理：

- **闲置资金自动买入底仓 ETF**（如沪深 300 ETF 或红利低波 ETF），不算空仓，也不需要 Agent 判断。
- 底仓 ETF 同时是**基准**：如果 Agent 选的个股长期跑不赢自己的底仓，就说明选股没有价值。
- 按市场状态分档设定**总权益仓位下限**，由代码根据指数是否站上 120 日均线等简单客观指标判断，不让 Agent 主观决定：

| 市场状态 | 判定（示例） | 总仓位区间 | 其中个股上限 |
|---|---|---|---|
| 进攻 | 沪深 300 在 120 日均线上方，且 20 日均线向上 | 70%-95% | 80% |
| 中性 | 其他情况 | 50%-80% | 50% |
| 防守 | 沪深 300 在 120 日均线下方，且跌破 60 日均线 | 30%-50% | 20% |
| 熔断 | 账户回撤触发熔断（见 4.3） | 底仓下限 | 0%（暂停新开个股仓位） |

### 4.2 个股与组合约束

| 规则 | 建议默认值 |
|---|---|
| 单只个股仓位上限 | 20% |
| 持股数量 | 2-6 只个股（加底仓 ETF） |
| 单一行业上限 | 35% |
| 单笔最大风险 | 买入时就要设止损价；（买入价 − 止损价）× 股数 ≤ 总资产 1% |
| 个股止损 | 亏损 8%，或跌破买入时设定的止损价，二者取先到者；次日 14:45 执行 |
| 时间止损 | 持有 20 个交易日仍没达到预期且收益 <0，强制复核，默认卖出 |
| 最短持有期 | 3 个交易日（止损除外），防止频繁换手 |
| 换手限制 | 每周新开个股仓位不超过 3 笔 |
| 股票池排除 | ST/*ST、上市不满 60 个交易日的次新股、退市整理股、日均成交额 <1 亿；**你没有权限交易的板块**（如科创板 688、北交所）也要排除，否则实盘无法跟随 |
| 追高限制 | 当日涨幅 >7% 或近 5 日涨幅 >25% 的股票不买 |

### 4.3 账户级回撤熔断

| 账户从高点回撤 | 动作 |
|---|---|
| ≥ 8% | 个股总仓位上限降一档；复盘 Agent 必须写专项复盘 |
| ≥ 12% | 进入熔断：只保留底仓，暂停新开个股仓位 10 个交易日 |
| ≥ 18% | 整个系统暂停，等你人工复核后才能恢复 |

## 五、自我学习与进化机制

"自我学习"最大的风险不是学不会，而是**把运气当成能力、把噪音当成规律**。所以要分层，并设门槛。

### 5.1 三层记忆

| 层级 | 内容 | 写入频率 | 谁能改 |
|---|---|---|---|
| **交易日志** | 每笔交易的买入逻辑、预期持有期、目标价、止损价、证伪条件、置信度、提示词版本、模型名 | 每笔交易 | 代码（Agent 提供内容） |
| **复盘记录** | 每日/每周复盘：结果对照当初逻辑，归类错误类型（选股错、时机错、仓位错、纪律执行错、运气） | 每日/每周 | 复盘 Agent |
| **经验库** `evolution/lessons.md` | 被多次验证的经验，每条附证据（涉及的交易编号、次数、胜率） | 每周 | 进化 Agent 提议 → 你批准 |

研究和决策时，首席研究员必须读取经验库，并在报告中说明本次决策用到了哪几条经验。

### 5.2 进化流程（每周一次）

1. **归因**：代码统计各维度表现，例如哪类信号的胜率和盈亏比高、哪个子代理的判断与实际收益相关性高、置信度是否校准（说"高置信度"的交易是否真的更常赚钱）。
2. **提案**：进化 Agent 根据归因结果提出 1-3 条改进提案，每条写明：改什么（具体到提示词或参数）、证据、预期效果、可能的副作用。
3. **门槛**：一条提案至少有 **15 笔相关交易**作为证据才允许提出。证据不足的只记为"观察项"。
4. **影子测试**（推荐）：批准的提案不直接替换主策略，而是开一个**挑战者账户**并行模拟 1-2 个月。挑战者在收益回撤比上明显优于主策略，才正式替换。
5. **版本化**：提示词和参数的每次修改都 git 提交，打版本号（如 `strategy-v1.3`），写入 `evolution/CHANGELOG.md`。

### 5.3 什么可以进化，什么不行

| 可以进化（需你批准） | 不允许 Agent 修改 |
|---|---|
| 选股初筛的因子和阈值 | 风控配置 `config/risk.yaml` |
| 子代理提示词中的分析重点 | 账本与历史交易记录 |
| 各维度在决策中的权重 | 撮合与成本规则 |
| 经验库条目 | 上线实盘的标准 |

## 六、评价体系

### 6.1 核心指标

**主目标：收益回撤比（Calmar = 年化收益 ÷ 最大回撤）**，它直接对应"回撤尽量小、收益尽量高"。

| 类别 | 指标 |
|---|---|
| 收益 | 累计收益、年化收益、相对基准的超额收益 |
| 风险 | 最大回撤、回撤持续天数、波动率、下行波动率 |
| 风险调整收益 | Calmar、Sharpe、Sortino |
| 交易质量 | 胜率、盈亏比、平均持有天数、换手率、成本占收益比 |
| 决策质量 | 置信度校准、各子代理信号的贡献、违反纪律次数 |

### 6.2 必须对比的基准

| 基准 | 用来回答什么问题 |
|---|---|
| 沪深 300 / 中证 1000 指数 | 跑赢市场了吗？ |
| 只持有底仓 ETF | Agent 选股和择时到底有没有增加价值？ |
| **随机选股对照组**：同样的风控规则，候选池里随机挑股票 | 收益来自 Agent 的判断，还是只是来自风控规则和市场行情？**这是判断"真本事还是运气"最关键的对照** |
| 纯量化初筛组：直接买初筛排名前 N 名，不经 Agent 研究 | 昂贵的 LLM 深度研究是否比简单量化排序更好？ |

后三个对照组都由代码自动运行，几乎不花成本。

## 七、上线实盘的标准（现在就定好，之后不改）

几个月后看收益时，人很容易被一段好行情说服。所以标准要**提前写死**：

| 条件 | 建议标准 |
|---|---|
| 运行时长 | ≥ 6 个月，且至少经历过一次指数 10% 以上的回调 |
| 样本量 | ≥ 40 笔已平仓的个股交易 |
| 回撤 | 最大回撤 ≤ 15%，且小于同期沪深 300 的最大回撤 |
| 收益回撤比 | Calmar 高于底仓 ETF 和随机选股对照组 |
| 稳健性 | 去掉收益最高的 3 笔交易后，仍跑赢底仓 ETF |
| 纪律 | 没有出现系统故障导致的错误交易；风控规则从未被绕过 |

**满足条件后，也只建议分步跟随**：先用计划资金的 20% 跟随 2-3 个月，同时模拟盘继续运行，对比实盘和模拟的差异（滑点、执行偏差、你自己是否能做到不干预）。差异可控再逐步加仓。

## 八、你可能漏掉的点

1. **卖出逻辑比买入更重要。** 你的想法只提到买入，但回撤主要取决于卖出：止损、止盈、逻辑证伪、时间止损、调仓。每晚必须逐只复核持仓，给出"继续持有/减仓/卖出"及理由。
2. **LLM 不能用于历史回测。** 模型的训练数据里已经包含过去的行情，拿它"回测"去年会严重高估效果。所以只能做前向模拟，这也是为什么需要几个月时间。量化初筛的规则倒是可以用历史数据回测。
3. **模型更新会改变策略。** Qoder 背后的模型升级后，同样的提示词可能给出不同的判断。每笔交易要记录模型名称，模型变更视同一次策略版本变更。
4. **小资金的整手问题。** 资金不大时，很多高价股连一手都买不起，或者一手就超过单票上限。初筛就要过滤"买不起"的股票。
5. **全市场深度分析成本太高。** 每晚对几千只股票跑 8 个子代理不现实。用"量化初筛 → 轻量点评 → 深度研究 3-5 只"的漏斗。持仓复核每晚必做。
6. **运行可靠性。** Qoder 的定时任务要求电脑开机、Qoder 在运行，合盖睡眠会错过任务。需要：
   - 幂等：同一个任务跑两遍不会重复下单（按日期和订单编号去重）；
   - 补跑：错过 14:45 执行时，按规则顺延或放弃，绝不事后挑价格补单；
   - 告警：任务失败、数据取不到、风控熔断时通知你；
   - 数据校验：取到的数据日期不是最新交易日时，当天不交易。
7. **数据源会失效。** AKShare 依赖第三方网站，接口经常变。取数失败时，系统的默认动作是"不交易"，而不是"凭印象交易"。
8. **统计显著性有限。** 几个月、几十笔交易，能排除"明显没用"，但很难证明"一定有用"。A 股风格切换快，一种行情里有效的方法换一种行情可能失效。所以上线后也要持续对照模拟盘。
9. **你自己也是变量。** 实盘跟随时最常见的问题是：亏损时不敢执行止损、盈利时提前卖出、看到热点忍不住加仓。如果做不到严格跟随，模拟盘的成绩就不代表你的实盘成绩。建议实盘阶段记录每次"没有按系统执行"的情况。
10. **可视化。** 每晚自动生成一页报告：净值曲线（含所有基准）、回撤曲线、持仓、当日成交、风控状态，方便你每天花一分钟查看。

## 九、目录结构

```
a-stock-investment/
├── config/
│   ├── risk.yaml              # 风控规则（只有你能改）
│   ├── broker.yaml            # 费率、滑点、初始资金
│   └── strategy.yaml          # 初筛因子、权重（可进化，需批准）
├── sim/                       # 确定性代码
│   ├── calendar.py            # 交易日历
│   ├── screen.py              # 量化初筛（只服务 quant / random 对照组）
│   ├── pool.py                # 主策略候选池：全市场多路召回 + 分诊
│   ├── risk.py                # 订单风控校验
│   ├── broker.py              # 撮合与成本
│   ├── ledger.py              # 账本、持仓、净值
│   ├── settle.py              # 盘后结算（估值、除权除息、回撤、止损）
│   ├── strategies.py          # 各账户订单草稿
│   ├── attrib.py              # 策略归因
│   └── report.py              # 指标计算与每日报告
├── accounts/                  # 每个账户一个目录，由代码写入
│   ├── main/                  # 主策略账户：state.json / trades.csv / nav.csv
│   ├── quant/                 # 量化初筛对照组
│   ├── random/                # 随机选股对照组
│   ├── etf_band/              # 仓位对照组：ETF 跟当日仓位区间上沿
│   └── etf/                   # 底仓 ETF 对照组（固定 98%）
├── orders/<交易日>/           # <账户>.json 冻结订单 + <账户>.draft.json 草稿 + MANIFEST.json
├── journal/
│   ├── decisions/             # 每笔交易的决策档案
│   ├── daily/                 # 每日复盘
│   └── weekly/                # 每周复盘
├── evolution/
│   ├── lessons.md             # 经验库
│   ├── proposals/             # 进化提案
│   └── CHANGELOG.md           # 策略版本记录
└── reports/                   # 每日可视化报告
```

新增 3 个 Agent：**组合经理**（汇总研究、输出订单建议）、**复盘官**（每日/每周复盘、错误归类）、**策略进化官**（每周归因与提案）。

## 十、分阶段实施

| 阶段 | 内容 | 预计 |
|---|---|---|
