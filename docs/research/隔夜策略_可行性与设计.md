# 隔夜策略（尾盘买、次日开盘卖）可行性与设计（草案，2026-11-01）

> 状态：**已批准并实现**（2026-11-01：用户确认三账户各 10 万、风控放开按建议、定时任务交 Qoder CN）。实现见 `sim/overnight.py`、`config/overnight*.yaml`，定时任务交接见 `docs/automation/overnight-handoff.md`。

## 1. 想法与优点

规则：交易日 14:5x 选股 → **收盘集合竞价（14:57–15:00）买入** → 次日 **开盘集合竞价（9:15–9:25）卖出**。

- 买卖都在集合竞价成交，成交价就是当日收盘价 / 次日开盘价，**模拟和实盘几乎没有执行差异**（小资金下冲击可忽略）。
- 持仓只过一夜，止损、移动止损、仓位节奏这些"交易手法"全部消失，收益只取决于选股。
- 符合 T+1：今天买，明天卖。

## 2. 先看数据：基准胜率是负的

样本：中证 800 随机 150 只，2024-01 ~ 2026-10，新浪前复权日线，10.0 万个"股票×夜晚"（脚本见本次会话 scratchpad `probe.py`，口径：隔夜收益 = 次日开盘 / 当日收盘 − 1；成本 ≈ 0.102%/来回 = 佣金万 2.5×2 + 印花税 0.05% + 过户费，未计 5 元最低佣金）。

| 分组 | 样本 | 平均隔夜收益 | 胜率(>0) | 扣成本后均值 |
|---|---|---|---|---|
| 全部 | 100,269 | **−0.049%** | 35.4% | **−0.151%** |
| 对照：日内（开→收） | 100,269 | +0.106% | 48.3% | +0.004% |
| 当日跌 >5% | 2,512 | −0.133% | 44.5% | −0.235% |
| 当日 0~+2% | 31,599 | −0.074% | 33.8% | −0.176% |
| 当日 +5%~涨停下（**能买到**） | 3,320 | +0.243% | 38.9% | +0.141% |
| ↳ 且收在全天最高附近 | 666 | +0.510% | 43.2% | +0.408% |
| 收盘封涨停（**基本买不到**） | 674 | +2.338% | 70.0% | +2.236% |

结论：
1. **A 股的隔夜收益平均为负**（和学术上"T+1 下隔夜收益之谜"的发现一致）：随便买，每晚亏约 0.15%，一年 240 次大约亏 30%。选股必须先跨过这个坑。
2. **"高胜率"的组合几乎都集中在买不到的票上。**封死涨停的票隔夜胜率 70%，但收盘时卖单为零，排队买不到；回测如果不剔除，会得到一个漂亮但假的策略。这是这类策略最主要的陷阱。
3. 能买到的强势尾盘股有正期望（每次 +0.14%~+0.41% 扣费后），但**胜率只有 39%~43%**，靠少数大幅高开赚钱。现实的目标应该是**扣费后正期望**，而不是胜率高于 60%。
4. 上表用的是收盘价判断"收在最高"，存在前视偏差（14:50 时还不知道收盘价），真实效果会打折扣。所以必须用 14:50 的快照重新验证。

## 3. 核心问题与实验设计（2026-11-01 用户修订：以 Agent 决策为主）

要回答的问题：**以 Agent 智能决策为主，隔夜胜率和收益能否明显高于纯量化和随机？**
Agent 自己用不用量化工具不重要，量化在这里只是 Agent 手里的一件工具，同时也是对照组。

### 3.1 三组同时纸面交易（同规则、同成本、同可成交性）

| 账户 | 谁决策 | 作用 |
|---|---|---|
| `overnight_agent`（主） | Agent：读新闻、公告、板块逻辑、情绪、盘口，自由调用量化打分等工具，**最终选择权在 Agent** | 被检验的对象 |
| `overnight_quant` | 纯因子打分前 N，无 Agent | 回答"Agent 的判断是否比公式强" |
| `overnight_random` | 从同一可交易池随机挑 N 只 | 回答"是否只是赚了市场 beta" |

### 3.2 为什么只能前向检验，不能回测 Agent

LLM 训练数据覆盖了 2024~2026 的大量行情和新闻，让它"回到过去选股"会不自觉用到结果，回测必然虚高。**Agent 的能力只能从今天起前向纸面交易来验证。**量化组可以回测，但 Agent 组不行，这也是三组必须同时跑的原因。

### 3.3 Agent 每次决策必须留下可打分的预测

每只入选（以及每只被 Agent 否掉的量化候选）都写：
- `p_win`：次日开盘价 > 买入价 × (1+成本) 的概率
- `exp_gap`：预期开盘涨跌幅
- `thesis`：一句话逻辑（属于哪类：题材发酵 / 业绩催化 / 板块龙头尾盘抢筹 / 超跌修复 / ……）
- `kill`：今晚出现什么信息说明判断错了

这样就能算 **校准度（Brier 分数）**：Agent 说 60% 的票是否真的六成高开；还能按逻辑类型归因，找出 Agent 真正擅长的那一类，而不是笼统看总收益。

### 3.4 判定标准（事先写死，避免事后找理由）

- 每组至少 200 笔（每晚 3~5 只，约 2~3 个月）。
- Agent 组相对量化组：扣费后每笔均值差 > 0 且 bootstrap 95% 置信区间不跨 0，才算"Agent 有增益"。
- 胜率作为辅助指标（第 2 节显示基准只有约 35%，Agent 组若稳定 > 50% 即是很强的证据）。
- 空仓也是决策：Agent 可以判断"今晚不做"，空仓夜按 0 收益计，单独统计空仓的择时价值。

## 4. Agent 一天的工作节奏

14:50 才开始研究来不及，所以把研究摊到全天，14:50 只做最后确认：

| 时点 | 动作 |
|---|---|
| 前一晚 / 盘前 | 读隔夜外盘、政策新闻、今日公告、龙虎榜，形成 **主线假设**（哪些板块今天可能走强）和 20~40 只观察名单 |
| 11:35 午间 | 用上午盘面验证主线，名单收缩到 10~15 只，逐只查公告与风险 |
| 14:40 | 拉全市场快照 + 量化打分（工具）+ 涨停池/炸板/板块排名；把新冒出来的强势股补进来快速核查 |
| 14:50 | **Agent 最终决定** 0~5 只、权重、每只的 p_win / thesis / kill；写入订单 |
| 14:53 | 风控校验（可成交性、单票上限、黑名单），冻结订单，之后不可改 |
| 15:00 | 按收盘价成交（收盘封涨停视为未成交） |
| 次日 9:25 | 按开盘价卖出（一字跌停卖不出则顺延，按真实结果记账） |
| 次日盘后 | 打分：逐笔对比预测与结果，写进经验库，供次日 Agent 读取 |

Agent 的信息优势主要在量化难以表达的地方：今晚是否有行业政策/会议、题材是否处于发酵初期、公告的真实含义、板块内谁是龙头、情绪退潮的迹象、今晚外盘重大数据（如美联储议息）带来的隔夜风险。

## 5. 防止 Agent 自我欺骗

1. **事先登记**：每晚决策时间戳早于收盘，事后不能改；冻结文件只能由 `python -m sim` 写。
2. **不看答案**：决策环节禁止读取次日数据；复盘才可以看。
3. **经验库只记可证伪的规律**（例如"情绪退潮日的高位题材股隔夜胜率低"），每条附样本数，样本 < 20 的只算观察。
4. **可成交性真实建模**：涨停封死买不到、跌停卖不出、停牌，三组同样处理。
5. **进化官每周复盘**，提出调整提案，仍需你批准才生效（沿用现有机制）。
